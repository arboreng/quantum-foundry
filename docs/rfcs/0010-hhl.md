# RFC-0010: HHL (Harrow-Hassidim-Lloyd) Linear Systems Algorithm From Scratch

Status: Draft

## Vision

Educational quantum computing reference implementation of the HHL
algorithm: given a Hermitian matrix `A` and efficient preparation of a
state `|b>`, produce (up to normalization, conditioned on a postselected
ancilla measurement) the quantum state `|x>` proportional to the solution
`x = A^-1 b` of the linear system `Ax = b`.

## Why This Should Exist

HHL is the last algorithm on [VISION.md](../../VISION.md#long-term-vision)'s
long-term list. It's also this repo's first algorithm with a genuinely new
success-and-failure shape: every prior RFC either runs a fixed circuit
with a provable success probability (Shor through QPE) or drives a
classical optimization loop toward a best-found answer (QAOA, VQE). HHL
does neither — it runs a *fixed* circuit once, but the useful output only
exists in the b-register *conditioned on measuring a specific ancilla
qubit as `1`* (postselection); the rest of the time, the shot is simply
discarded. It reuses [RFC-0007](0007-quantum-phase-estimation.md) (QPE)'s
controlled-power-of-unitary oracle pattern directly, as the eigenvalue-
estimation subroutine at HHL's core.

## Prior Art

-   Harrow, Hassidim, Lloyd, "Quantum algorithm for linear systems of
    equations" (2009).
-   [algorithms/qpe/](../algorithms/qpe/) — the phase-estimation subroutine
    this RFC reuses conceptually (a controlled-power-of-unitary `Oracle`
    protocol, structurally the same shape), applied here to estimate `A`'s
    eigenvalues on a "clock" register entangled with `|b>`'s decomposition
    in `A`'s eigenbasis.
-   `arithmetic/qft.py` — this RFC's clock-register uncomputation reuses
    `inverse_qft` directly (a fourth consumer, after
    `algorithms/shor/circuit.py`, `arithmetic/adders.py`, and
    `algorithms/qpe/circuit.py`).

## Architecture

-   `algorithms/hhl/oracles.py` — an `Oracle` protocol
    (`controlled_power_gate(power) -> Gate`), for a Hermitian matrix of
    the form `A = a*I + b*X` (arbitrary real `a`, `b` — not one hardcoded
    matrix, but always diagonal in the `|+>`/`|->` basis, with eigenvalues
    `a+b` and `a-b`). `DiagonalXOracle(a, b)`: since `I` and `X` commute,
    `exp(-i*A*t*power)` factors exactly into a controlled global phase
    (`P(-a*t*power)` on the control qubit) times `RX(-2*b*t*power)` on the
    target — closed-form, no Trotterization needed.
-   `algorithms/hhl/circuit.py` — `build_hhl_circuit(oracle, t, n_clock,
    c_constant, b_state_prep)`: an `n_clock`-qubit clock register, a
    1-qubit b-register, and a 1-qubit rotation ancilla. `b_state_prep` on
    the b-register, then QPE (`H^n_clock`, controlled
    `oracle.controlled_power_gate(2**k)` per clock qubit, then
    `arithmetic.qft.inverse_qft` on the clock register), then a
    *multiplexed* `RY` rotation on the ancilla — conditioned on the clock
    register's measured-as-an-integer value `k`, angle `2*arcsin(
    c_constant / lambda_k)` for `lambda_k = 2*pi*k / (t * 2**n_clock)`
    (`0` for `k=0`, avoiding division by zero for the null eigenvalue
    branch) — then QPE's inverse, uncomputing the clock register back to
    `|0...0>` (exact by construction, for this RFC's chosen `t`/`n_clock`
    making eigenvalues land on exact `n_clock`-bit binary fractions,
    mirroring RFC-0007's `PhaseGateOracle` choice). Finally, measure the
    ancilla (and optionally the b-register).
-   `algorithms/hhl/execution.py` — the standard `Executor` protocol +
    `AerExecutor`.
-   `algorithms/hhl/implementation.py` — `solve_linear_system(oracle, t,
    n_clock, c_constant, b_state_prep, shots)`: runs the circuit, returns
    the ancilla-`1` success probability and the b-register's measured
    distribution conditioned on that postselection — this repo's first
    "postselect on an ancilla, discard the rest" success pattern, distinct
    from every prior RFC's bounded-retry or classical-optimization-loop
    shape.

## Explicit Non-goals (v0.2)

-   Only a 2x2 system: `A = a*I + b*X` (arbitrary real `a`, `b`, but always
    diagonal in the `|+>`/`|->` basis) — no general Hermitian matrix, no
    higher-dimensional systems, no sparse-matrix Hamiltonian-simulation
    techniques (Trotter-Suzuki, linear combination of unitaries,
    qubitization).
-   `t` and `n_clock` chosen so the demo instance's eigenvalues land on a
    terminating `n_clock`-bit binary expansion (mirrors RFC-0007's
    `PhaseGateOracle` choice) — general (possibly irrational or
    non-terminating) eigenvalues are out of scope, the same limitation
    RFC-0007 already documents for QPE generally.
-   No condition-number analysis or success-probability bound derivation
    beyond citing Harrow-Hassidim-Lloyd's original result.
-   No hardware execution, fault tolerance, distributed simulation, or GPU
    acceleration.
