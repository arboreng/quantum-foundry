# RFC-0009: Variational Quantum Eigensolver From Scratch

Status: Draft

## Vision

Educational quantum computing reference implementation of the Variational
Quantum Eigensolver (VQE): given a Hamiltonian `H` (a Hermitian operator on
`n` qubits), prepare a parameterized trial state (an "ansatz") and use a
classical optimization loop to minimize `<psi(theta)|H|psi(theta)>`,
approximating `H`'s ground-state energy via the variational principle
(`<psi|H|psi> >= E_0` for any `|psi>`, with equality iff `|psi>` is a true
ground state).

## Why This Should Exist

[RFC-0008](0008-qaoa.md) (QAOA) established this repo's first hybrid
classical-quantum pattern — a parameterized circuit plus a
`scipy.optimize` classical outer loop — and explicitly flagged VQE as its
natural stretch goal, sharing that pattern. But QAOA's cost Hamiltonian is
*diagonal* in the computational basis (`C|z> = cost(z)|z>`), so its
expectation value is read directly off measured bitstrings with no basis
change. VQE generalizes this to an *arbitrary* Hermitian `H`, expressed
here as a weighted sum of Pauli strings (`I`/`X`/`Y`/`Z` per qubit), which
requires actually rotating into each term's measurement basis before
reading off `+-1` eigenvalues and combining them per term. That basis-
rotation-and-recombination step is the qualitatively new piece this RFC
adds to the classical-optimization-loop family. It's also the
second-to-last algorithm on [VISION.md](../../VISION.md#long-term-vision)'s
long-term list — only HHL remains after this.

## Prior Art

-   Peruzzo et al., "A variational eigenvalue solver on a photonic quantum
    processor" (2014) — the original VQE paper.
-   McClean et al., "The theory of variational hybrid quantum-classical
    algorithms" (2016).
-   [algorithms/qaoa/](../algorithms/qaoa/) — the classical-optimization-loop
    pattern this reuses (`scipy.optimize.minimize`, COBYLA), generalized
    from a diagonal cost function read directly off bitstrings to an
    arbitrary Pauli-sum Hamiltonian requiring per-term basis rotation.

## Architecture

-   `algorithms/vqe/hamiltonians.py` — `PauliTerm` (`coefficient: float`,
    `paulis: str`, one character in `{"I", "X", "Y", "Z"}` per qubit) and a
    `Hamiltonian` protocol (`n_qubits`, `terms: list[PauliTerm]`).
    `TransverseFieldIsingHamiltonian(n_qubits, j_coupling, h_field)`: the
    1D transverse-field Ising model `H = -J * sum_i Z_i Z_{i+1} - h *
    sum_i X_i` (open chain) — small, well-known, exactly diagonalizable
    (via `numpy`, already a dependency) for validation, and requires no
    quantum-chemistry electronic-structure mapping (see Non-goals).
-   `algorithms/vqe/circuit.py` — `ansatz_circuit(n_qubits, params, reps)`:
    a hardware-efficient ansatz (`reps` layers of per-qubit `RY(theta)`
    plus a ladder of entangling `CX` gates, then one final `RY` layer —
    `n_qubits * (reps + 1)` parameters total). `measurement_circuit(
    n_qubits, params, reps, term)`: the ansatz followed by the
    basis-rotation gates for a given Pauli term (`H` for `X`; `Sdg` then
    `H` for `Y`; nothing for `Z`/`I`) and a measurement of every qubit.
-   `algorithms/vqe/execution.py` — the standard per-algorithm `Executor`
    protocol + `AerExecutor`.
-   `algorithms/vqe/implementation.py` — `expectation_value(hamiltonian,
    params, reps, executor, shots)`: for each non-identity Pauli term, run
    its measurement circuit and combine each shot's `+-1` parity (the
    product of `(-1)^bit` over the term's non-`I` qubits) weighted by
    counts; sum `coefficient * <term>` over all terms (a pure-identity
    term, if present, contributes its coefficient directly with no circuit
    execution). `solve_ground_state(hamiltonian, reps=1, executor=None,
    shots=1000)`: `scipy.optimize.minimize` (COBYLA, matching RFC-0008)
    tunes `params` against `expectation_value`, then returns the optimized
    params and a final higher-shot-count energy estimate.

## Technology Choices

Python, Qiskit, `scipy.optimize` (already a direct dependency since
RFC-0008), `numpy` (already a dependency; used only for exact
diagonalization in tests/benchmarks, not in the algorithm itself). No
quantum-chemistry package (no PySCF, no OpenFermion) — Hamiltonians are
hand-specified Pauli sums, not derived from molecular structure.

## Explicit Non-goals (v0.2)

-   No quantum chemistry: no fermionic-to-qubit mapping (Jordan-Wigner,
    Bravyi-Kitaev), no molecular Hamiltonians, no PySCF/OpenFermion
    dependency — Hamiltonians are hand-specified Pauli-string sums (e.g.
    transverse-field Ising) only.
-   No UCCSD or other chemistry-inspired ansatz — a hardware-efficient
    (`RY` + `CX`-ladder) ansatz only.
-   No gradient-based optimization (e.g. the parameter-shift rule) —
    COBYLA only, matching RFC-0008.
-   No measurement grouping / qubit-wise-commuting-term batching — one
    circuit execution per non-identity Pauli term, even when several terms
    could in principle share a measurement basis.
-   No hardware execution, fault tolerance, distributed simulation, or GPU
    acceleration.
-   No convergence-rate analysis — only the variational principle's basic
    guarantee (`<psi|H|psi> >= E_0`) is invoked, not a bound on how close
    COBYLA gets in practice.

## Stretch Goals

Measurement grouping (batching qubit-wise-commuting Pauli terms into
shared circuit executions, cutting the number of circuit runs per
`expectation_value` call); parameter-shift gradients (enabling
gradient-based optimizers, compared against COBYLA); a Heisenberg-model
Hamiltonian alongside transverse-field Ising; HHL (the one remaining
algorithm on VISION.md's long-term list).
