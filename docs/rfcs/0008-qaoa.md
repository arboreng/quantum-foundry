# RFC-0008: Quantum Approximate Optimization Algorithm From Scratch

Status: Draft

## Vision

Educational quantum computing reference implementation of QAOA (Quantum
Approximate Optimization Algorithm): a hybrid classical-quantum algorithm
approximating solutions to combinatorial optimization problems, targeting
MaxCut (partition a graph's vertices to maximize edges crossing the
partition) as the standard demonstration.

## Why This Should Exist

Every algorithm in this repo so far (RFC-0001 through RFC-0007) is a
**fixed** circuit run once (or with a bounded retry loop) to recover a
definite answer with a provable success-probability guarantee. QAOA is a
genuinely different flavor: a **parameterized** circuit whose parameters
are tuned by a classical optimization loop against a problem-dependent cost
function, with no single correct measured bitstring to check against — the
answer is "the best one found," approximate by construction. This RFC
establishes the pattern for this whole family (QAOA, and eventually VQE,
both on VISION.md's long-term list) in this repo.

## Prior Art

-   Farhi, Goldstone, Gutmann, "A Quantum Approximate Optimization
    Algorithm" (2014).
-   [algorithms/grover/](../algorithms/grover/) — the closest existing
    analog (a phase-oracle-based construction), though QAOA's cost unitary
    is parameterized by a continuous angle `gamma` rather than fixed, and
    is followed by a mixer and a classical outer loop rather than a fixed
    iteration count.

## Architecture

-   `algorithms/qaoa/problems.py` — a `Problem` protocol (`n_qubits`,
    `cost_gate(gamma) -> Gate`, `cost_value(bitstring) -> float`) — the
    per-problem-instance abstraction, analogous in spirit to every prior
    RFC's `Oracle` but centered on a classical cost function rather than a
    marking/period/phase oracle. `MaxCutProblem(edges, n_qubits)`: cost
    gate built from one `RZZ`-equivalent (`CX`-`RZ`-`CX`) gate per edge;
    `cost_value` classically counts cut edges for a given bitstring.
-   `algorithms/qaoa/circuit.py` — `mixer_gate(n_qubits, beta)` (one `RX`
    per qubit) and `build_qaoa_circuit(problem, gammas, betas)`: `H^n`
    (uniform superposition over all `2^n_qubits` cuts) -> `p = len(gammas)`
    layers of (`problem.cost_gate(gammas[l])`, `mixer_gate(n_qubits,
    betas[l])`) -> measure.
-   `algorithms/qaoa/execution.py` — the standard `Executor` protocol +
    `AerExecutor`.
-   `algorithms/qaoa/implementation.py` — `expectation_value(problem,
    gammas, betas, executor, shots)` (average `cost_value` over measured
    counts) and `solve_maxcut(edges, n_qubits, p, executor)`, using
    `scipy.optimize.minimize` (new direct dependency — generic numerical
    optimization isn't quantum-specific, unlike e.g.
    [algorithms/simon/](../algorithms/simon/)'s from-scratch GF(2) linear
    algebra, so reimplementing it wouldn't add educational value) to tune
    `(gammas, betas)` against `-expectation_value`, then returns the
    best-measured bitstring under the optimized parameters.

## Technology Choices

Python, Qiskit, `scipy.optimize` (new direct dependency, already present
transitively via qiskit/qiskit-aer).

## Explicit Non-goals (v0.2)

-   No problems beyond MaxCut (no graph coloring, no general QUBO/Ising
    encodings) — a future RFC could generalize `Problem` further.
-   No hardware execution.
-   No fault tolerance, distributed simulation, or GPU acceleration.
-   No approximation-ratio guarantees or worst-case analysis beyond citing
    Farhi et al.'s original results — this is a working reference
    implementation, not a performance-guarantee study.
-   No warm-starting or parameter-transfer heuristics between problem
    instances (each `solve_maxcut` call optimizes from scratch).

## Stretch Goals

VQE (the natural next hybrid-algorithm RFC, sharing this RFC's
classical-optimization-loop pattern); QUBO/Ising-model generalization of
`Problem` beyond MaxCut; comparison of classical optimizers
(`scipy.optimize`'s COBYLA vs. gradient-based methods) on the same problem
instance.
